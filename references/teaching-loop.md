# Adaptive teaching loop

Use this reference to run a learning interaction, respond to mistakes, control cognitive load, or choose how the learner produces notes.

## One small loop

Use one coherent loop at a time:

1. **Retrieve or attempt.** Ask for a prediction, explanation, example, or first attempt before teaching.
2. **Ground.** Present a concrete case, table, analogy with explicit limits, observable example, or small problem.
3. **Name the principle.** Add no more than one or two new concepts and connect them to the map.
4. **Represent.** Use plain language first. For a procedure, show readable pseudo code before implementation. Add formulas, notation, or terminology only after their pieces have a concrete meaning.
5. **Practise.** Ask one question or one bounded task. Require a prediction before running code or revealing the result when prediction is meaningful.
6. **Feedback.** Identify what the reasoning established, the exact gap, and the smallest next correction.
7. **Record.** Save evidence and update mastery only after observing the learner's performance.

Stop after a completed loop when the learner is tired or the session goal is met. Lesson size must not override cognitive state.

## Layered help

When an attempt fails, increase support gradually:

| Hint level | Intervention |
|---|---|
| 0 | No help beyond the task contract |
| 1 | Point to the step, assumption, or representation containing the error |
| 2 | Give a leading constraint, partial example, or smaller subproblem |
| 3 | Change representation or reteach the missing prerequisite |
| 4 | Demonstrate a complete solution, then require a fresh analogous attempt |

Record the highest hint level used. A correct answer after level 3 or 4 is learning evidence, but not independent-application evidence.

## Cognitive-load response

Treat these as signals, not diagnoses:

- accuracy or explanation quality drops across nearby prompts;
- the learner repeats the same error after feedback;
- hint level rises;
- the learner loses the relationship between symbols and the concrete example;
- the learner explicitly reports fatigue, anxiety, overload, or a wish to stop.

Respond by changing one thing: reduce the frontier, return to a concrete representation, shorten the task, repair one prerequisite, switch from new material to recall, or checkpoint and stop.

Do not add a motivational lecture. Make the workload smaller and the stopping point truthful.

## Learner-generated notes

For core nodes, ask the learner to produce a minimal reconstruction before generating polished notes. Suitable forms include:

- three sentences in their own words;
- a small concept map;
- pseudo code;
- a worked example with one explanation per step;
- a comparison table;
- a teach-back aimed at a beginner.

Correct false claims, preserve the learner's useful phrasing, and add only missing structure. Store the resulting note or artifact when it will support review or handoff.

## Interaction variants

Adapt without changing the evidence standard:

- Use challenge-first when the learner already has relevant experience and the task can safely reveal gaps.
- Use explanation-first when a missing model makes attempts arbitrary.
- Use build-first when an observable artifact supplies fast feedback.
- Use theory-first only when definitions or formal constraints are themselves prerequisites.

State why a material variant is being used.
