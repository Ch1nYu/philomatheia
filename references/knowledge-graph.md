# Goal-weighted spiral BFS

Use this reference to build or revise the knowledge graph, select frontier nodes, advance a spiral pass, or decide completion.

## Build the useful trunk

Start from the learner's desired ability and work backward through credible prerequisites. Map only enough structure to show major regions, route alternatives, and the first frontier. Expand nodes near the frontier when new evidence or sources justify them.

For every proposed node, ask:

- Does it contribute to the goal or a required prerequisite?
- What observable ability would show progress on it?
- What level of mastery is actually needed?
- Which source supports the content or prerequisite claim?

Defer decorative completeness. A large unverified graph creates false authority and consumes attention.

## Goal subgraph

Create the active goal subgraph by taking the prerequisite closure of the goal nodes. Assign each member:

- `required`: whether the current goal truly depends on it;
- `target_level`: the mastery needed for completion;
- `goal_weight`: relative value after prerequisites are eligible;
- a rationale and source for non-obvious inclusion.

Weights rank only eligible nodes. They must never bypass an unmet hard prerequisite.

## Spiral passes

Use the smallest set of passes that fits the project:

| Pass | Gate | Typical evidence |
|---|---|---|
| 1 | Recognize the node and its role | Classification, matching, a one-line connection |
| 2 | Explain and distinguish it | Unprompted explanation, comparison, prediction |
| 3 | Apply with support | Guided practice or constrained production |
| 4 | Apply independently | Representative task or verified artifact without material hints |
| 5 | Transfer | Novel problem, debugging, teach-back, or integration task |

Ordinary nodes may target level 2 or 4. Core goal nodes may target level 5. Do not force every node to the same depth.

## Active frontier

First filter for nodes whose prerequisites meet the current pass gate. Then rank eligible candidates using:

1. prerequisite urgency;
2. contribution to the goal subgraph;
3. due review or weak retained evidence;
4. integration value with another active node;
5. learner interest or immediate usefulness;
6. estimated cognitive and setup cost.

Normally select two or three roles:

1. a main progression node;
2. a support, repair, or due-review node;
3. an optional integration or transfer node.

Use fewer when there are not enough eligible candidates, the project is paused, or cognitive load requires it. Show the recommendation and reason, and let the learner override it.

## Pass gate

Before raising the pass:

1. List every required node in the goal subgraph.
2. Require each node to reach `min(current pass, node target level)`.
3. Keep weak required nodes active or under review.
4. Allow optional nodes to remain deferred.
5. Advance only after the gate is satisfied.

Do not use an average score to hide a failed prerequisite.

## Integration circle

A circle closes after the learner has touched a small coherent set of frontier nodes at the current pass. Integrate immediately with the smallest suitable task:

- compare two neighboring concepts;
- draw or repair a concept map;
- predict how changing one node affects another;
- solve a task requiring two or three nodes;
- produce a small artifact with a verification criterion.

Add an `integration` node when the relationship itself is a durable ability worth tracking.

## Route changes

Make small changes autonomously when evidence supports them: reorder eligible nodes, shrink the frontier, change representation or hint level, insert a supporting node that does not alter the goal, or repair an erroneous related edge.

Ask before changing the goal, target level, completion contract, required-node set, hard prerequisite structure, or major knowledge-map region. Store a major proposal outside the active approved subgraph until the learner agrees.

## Completion

Complete a project only when:

- every required node reaches its target level;
- recent evidence supports the claimed independence;
- the learner passes the agreed integrative task;
- unresolved limits and optional unexplored regions remain visible.

Completion is a project outcome, not a permanent claim that forgetting cannot occur.
